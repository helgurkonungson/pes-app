# Бесплатный ключ Gemini в один тап — настройка и публикация

Как это работает в приложении (ADR-021):

1. Пользователь нажимает «Бесплатный AI от Google (Gemini)» на экране ключа при первом запуске или в Настройках.
2. Экран согласия объясняет, что произойдёт, и предупреждает о данных бесплатного тарифа и регионах ЕС/UK/CH. Кнопка активна только после галочки «Мне есть 18 лет… принимаю условия Gemini API». Факт согласия сохраняется в профиле (`geminiConsent`: версия, время, способ).
3. **Автоматически** (если в сборке задан OAuth-клиент): нативный вход Google прямо в приложении (Android: Credential Manager + AuthorizationClient, без браузера; iOS: Google Sign-In). Приложение запрашивает доступ `cloud-platform` один раз. Затем оно находит или создаёт проект `chompbook-…` с меткой `created-by=chompbook`, включает `generativelanguage.googleapis.com`, создаёт ключ «Chompbook», ограниченный только Gemini API, и проверяет его (новый ключ начинает работать примерно за минуту). Токен доступа нигде не сохраняется, сразу выполняется выход. Ключ уходит в защищённое хранилище.
4. **Вручную**, как запасной вариант (OAuth не настроен, Google просит принять условия, лимит проектов и т. п.): страница ключей Google AI Studio открывается во встроенном браузере (Custom Tab / SFSafariViewController). После закрытия приложение само берёт ключ `AIza…` из буфера обмена; если не вышло, есть поле для вставки.

Пока OAuth-клиент не настроен, в сборках работает только ручной путь — это безопасно.

## Что нужно сделать (один раз, Олег)

В [Google Cloud Console](https://console.cloud.google.com/), в отдельном проекте, например «Chompbook app»:

1. **APIs & Services → Library**: включить *Cloud Resource Manager API*, *Service Usage API*, *API Keys API*. Через квоту этого проекта идут вызовы от имени пользователей.
2. **Google Auth Platform → Branding**: название Chompbook, почта поддержки, логотип, ссылки на домашнюю страницу и **политику конфиденциальности** (обязательно, см. ниже).
3. **Audience**: тип *External*. Пока приложение в режиме *Testing*, добавьте свои аккаунты в Test users (до 100 человек).
4. **Data access → Add scopes**: `https://www.googleapis.com/auth/cloud-platform` (плюс `openid`, `email`, `profile` — их просит плагин). Этот доступ считается чувствительным: для режима *In production* Google требует **проверку приложения** (описание, зачем нужен доступ, видео с демонстрацией, политика конфиденциальности на своём домене). До проверки пользователи увидят «Google hasn't verified this app», и работает только список тестовых пользователей.
5. **Clients → Create client**:
   - *Web application*: его Client ID и есть `GOOGLE_WEB_CLIENT_ID`.
   - *Android*: package `io.github.helgurkonungson.pes`, SHA-1 релизного ключа (снят с PES-0.9.0.apk): `2F:F3:49:4C:53:52:42:41:78:C0:07:4C:EC:D6:02:95:66:E5:84:EF`. Для Google Play добавьте ещё один Android-клиент с SHA-1 ключа *Play App Signing* (Play Console → App integrity).
   - *iOS* (когда появится iOS-приложение): Bundle ID → `GOOGLE_IOS_CLIENT_ID`. В `Info.plist` нужно добавить URL scheme (reversed client id) — по инструкции плагина `@capgo/capacitor-social-login`.
6. **GitHub → Settings → Secrets and variables → Actions → Variables**: `GOOGLE_WEB_CLIENT_ID` (и позже `GOOGLE_IOS_CLIENT_ID`). Это не секреты: client id и так виден внутри приложения.

После этого следующая сборка покажет «Войти через Google и получить ключ».

## Публикация: Google Play

- **Data safety**: приложение передаёт материалы пользователя и его вопросы в Google (Gemini API) с ключом самого пользователя. Укажите «Data shared: App activity / User-generated content → Google, для функциональности». Email и имя из входа Google не сохраняются. Ключ и токен остаются на устройстве.
- **Политика по AI-контенту**: нужна возможность пожаловаться на сгенерированный урок из приложения (в бэклоге: «Пожаловаться на урок»).
- **Возрастной рейтинг и целевая аудитория**: условия Gemini API запрещают приложения для детей и тех, которыми, скорее всего, пользуются дети. Target audience — 18+; Teacher Approved / Designed for Families не подходят.
- Facebook SDK исключён (`facebook: false`), поэтому разрешения AD_ID нет.

## Публикация: App Store

- **5.1.2(i)** — передача персональных данных стороннему AI только с явного согласия пользователя: экран согласия это и обеспечивает. Он показывается до любой отправки.
- **4.8 (Sign in with Apple)**: вход Google здесь не создаёт аккаунт в приложении, он нужен только чтобы получить ключ к стороннему сервису. Приложение работает и без входа, поэтому Sign in with Apple не требуется. Это стоит пояснить в заметках для ревьюера.
- **Возраст 18+** — по той же причине, что и в Google Play.
- На iOS работает только ручной путь, пока не задан `GOOGLE_IOS_CLIENT_ID`.

## Ограничения и риски

- Новый аккаунт Google без принятых условий Cloud не даст создать проект: приложение откроет AI Studio, чтобы пользователь один раз принял условия, и затем продолжит само.
- Лимит проектов в аккаунте Google — тогда только ручной путь.
- ЕЭЗ, Великобритания, Швейцария: бесплатный тариф там недоступен, и пользователь предупреждён. Ключ будет работать только при включённом биллинге в его проекте.
- Условия Google называют AI Studio / Gemini API инструментом «для разработчиков… не для потребительского использования». Модель «пользователь получает свой ключ» распространена, но перед публикацией её стоит показать юристу.
